# Design: Task 3–5 + 8–10 Integration (Hướng A — Giữ seam + Prisma thật)

> Date: 2026-10-07 | Basis: `docs/user-sequence-specifications.md` (UC01–UC07), `docs/BrewLite-CongNghePhanMem-fixed.md` §9–12
> Goal đã chốt: full-stack thật qua docker-compose (Next.js → NestJS → Postgres). DONE = menu → cart → POST /orders → POST /payments → receipt end-to-end.
> Hướng đã chọn: A — giữ contracts + PaymentService hiện tại, thêm Product/Order modules Prisma-backed. Không tạo bảng mới ngoài 5 entity.

## 1. Architecture

```
Next.js (page.tsx, ProductDetailModal new, cart Zustand persist, PaymentForm+voucher, lib/payment gateway mock/api switch)
  --REST/JSON--> NestJS (ProductController, OrderController, PaymentController)
  --> Postgres via Prisma (User, Product, Order, OrderItem, Payment — schema.prisma hiện tại giữ nguyên)
  --> Mock Gateway (charge/refund In-Memory, không DB)
```

- Seam: `IOrderRepository / IProductRepository / IPaymentRepository / IUserRepository` (backend/src/contracts) giữ nguyên chữ ký. Prod dùng Prisma impl, test dùng In-Memory stubs hiện tại → test 17/17 không vỡ.
- `AppModule` hiện chỉ import `PaymentModule` → thêm `ProductModule`, `OrderModule`, `AuthModule` (JWT guard cho POST /orders, GET /orders/me).
- Frontend `lib/api.ts#getProducts` đã có fallback `MOCK_PRODUCTS` → giữ, chỉ hết fallback khi backend thật trả 200.

## 2. Components (thay đổi tối thiểu)

**Frontend (reuse pricing.ts — nguồn duy nhất):**
- NEW `ProductDetailModal.tsx` (UC01 bước 111–114): props `Product`; Size radio S(+0)/M(+5k)/L(+10k) theo `SIZE_UPCHARGE`, topping checkbox Trân châu 5k / Kem cheese 8k / Thạch cà phê 6k theo `TOPPING_PRICES`; qty stepper min 1 max `product.stock`; live `calcUnitPrice*qty`; nút Thêm gọi `useCart.addItem(product,{size,toppings,quantity})`.
- EDIT `ProductCard.tsx`: click card / nút "Tùy chọn" mở modal (không sửa pricing).
- EDIT `PaymentForm.tsx` (UC05a bước 281–288, wireframe 4): thêm input voucher + nút Áp dụng; `BREWLITE10` → `discount=floor(total*0.1)`, `final=total-discount`; hiển thị Tổng / Giảm / Thực trả. Giữ nguyên method radio WALLET/CARD, error giữ giỏ (US-05).
- EDIT `lib/payment/*`: `PaymentRequest` thêm `orderId, voucherCode?`; `api-gateway` checkout 2 bước: `POST /orders {items}` → `orderId`, rồi `POST /payments {orderId,paymentMethod,voucherCode}` kèm `Idempotency-Key: uuid`, `Authorization: Bearer JWT`.

**Backend:**
- NEW `ProductModule`: `GET /products` (lọc `stock>0`, mapping đúng `normalize()` của frontend), `GET /products/:id`.
- NEW `OrderModule`: `POST /orders` (validate items qua class-validator, `total=sum(qty*unitPrice)`, lưu `PENDING`, 201 `{id,status,total,createdAt}`; thiếu JWT → 401); `GET /orders/me` (`JwtAuthGuard`, `ORDER BY createdAt DESC`); `PATCH /orders/:id` chuyển từ `PaymentController` về đây (chỉ nhận `CANCELLED`).
- EDIT `CreatePaymentDto`: xóa `shouldSimulateFailure` (stub hook dòng 14–17). Test failure đi qua gateway mock throw, không qua DTO.
- KEEP `PaymentService.processPayment` thứ tự charge-first (khớp sequence 2.4: `charge` bước 313 rồi group DB 326–335): idempotency hit → 200 cached không gọi gateway; miss → voucher nội bộ → charge → `assertTransition(PENDING→PAID)` → deduct stock optimistic-lock retry 3 → update PAID + loyalty `floor(final*0.1/1000)` + save Payment → 201.
- KEEP `cancelOrder`: `assertTransition(*→CANCELLED)`; PAID → `refund(amount thực thu)` + `restoreStock`; `PREPARING→CANCELLED` chặn 400.

## 3. Data flow (khớp PlantUML)

1. UC01 Menu: `FE→BE GET /products → DB stock>0 → FE render grid` (loading/empty/error — Task 3). Chọn món → modal tính client, không gọi BE.
2. UC02 Cart: `addItem/updateQty/removeItem` trong `useCart` (persist `brewlite-cart`), `lineTotal/cartTotal` từ pricing.ts, badge = count.
3. UC04 Tạo đơn: `POST /orders` (JWT) → `PENDING #id`.
4. UC05a Voucher (opt): FE `floor(total*0.1)` preview → gửi `voucherCode` → BE validate nội bộ cùng công thức.
5. UC05 Pay: `POST /payments` + `Idempotency-Key`: Hit 200 / Miss 201 (chi tiết §2). Fail → `PAYMENT_FAILED` 400, giỏ giữ nguyên → `POST /payments` retry (`PAYMENT_FAILED→PENDING→PAID`).
6. UC06 Hủy: `PATCH /orders/:id {CANCELLED}`: PENDING→CANCELLED trực tiếp; PAID→CANCELLED + refund + restore; PAYMENT_FAILED→CANCELLED/PENDING hợp lệ.
7. UC07 Receipt + history: receipt ngay sau 201 (`#id`, PAID, "Mời tới quầy"); `GET /orders/me` cho lịch sử.

## 4. Error handling

| Case | Spec ref | Behavior |
|---|---|---|
| Thiếu JWT POST /orders, GET /orders/me | 2.4 note 271 | 401, dừng |
| Thiếu/trùng Idempotency-Key | 2.4 alt 302–305 | thiếu → 400; hit → 200 cached, không gọi gateway |
| Gateway charge fail | 2.4 alt 316–321 | `PAYMENT_FAILED`, 400, giỏ giữ nguyên |
| Stock conflict sau charge | 2.4 note 329–331 | retry version 3 lần → fail: `refund(final)` + `restoreStock(deducted)` + `PAYMENT_FAILED`, 409 |
| Transition sai (`PREPARING→CANCELLED`) | 2.5 §C, §9.1 | `assertTransition` ném 400 |
| Voucher sai | 2.4 note 307–310 | discount=0, vẫn charge full, không lỗi |
| GET /products rỗng/lỗi | 2.1 note 107 | FE fallback mock + empty/error state, không crash |

## 5. Testing & DONE

- Backend `npm test`: (a) `assertTransition` chặn sai; (b) 2× cùng Idempotency-Key = 1 Payment + lần 2 là 200 cached; (c) concurrent deduct không oversell (version retry → 409); (d) voucher `floor(total*0.1)` + loyalty `floor(final*0.1/1000)`. Giữ 17/17 hiện tại xanh trước khi thêm Prisma impl test.
- `npm run build` backend + frontend pass; `docker compose up --build` E2E: menu thật (fromMock=false) → cart persist F5 → order PENDING → pay 201 → receipt #id → `GET /orders/me` thấy đơn.
- Không thêm entity/endpoint ngoài 10 endpoint §12.1; voucher/loyalty nội bộ `PaymentService`.

## Quyết định khóa (tránh diễn giải 2 nghĩa)

- Charge-first + compensate (refund+restore) là chuẩn, theo đúng thứ tự PlantUML 2.4 — không đổi sang deduct-first dù text Task 4 trong plan cũ ghi ngược.
- `PATCH /orders/:id` thuộc `OrderController`, `PaymentController` chỉ giữ `POST /payments`.
- Pricing FE/BE dùng chung bảng `SIZE_UPCHARGE/TOPPING_PRICES` + `floor()` — lệch 1đ cũng fail review.
